1. EXECUTIVE SUMMARY
================================================================

Project name:
Trippple Frontend

What it is:
A React + Vite + TypeScript frontend for an AI-assisted travel platform.

What the product tries to be:
A premium travel app that combines:
- AI travel planning
- maps and routing
- collaboration / group trips
- booking-style flows
- match/swipe discovery
- 360 / immersive exploration
- user/admin dashboards

What this workspace actually contains:
- frontend only
- no backend code
- no database code
- no server-side AI orchestration code

Important reality:
The docs in the repo sometimes describe a broader monorepo or backend that is not present in this workspace.
Another AI should not assume backend code exists locally.

Best mental model:
"This is a visually ambitious frontend prototype/product shell with real routing and many real API hooks, but some screens still use mock data or demo behavior."

5. ROUTING ARCHITECTURE
================================================================

Main route definition file:
- src/App.tsx

Route organization:
1. Public pages inside public Layout
2. A standalone maps route
3. API/auth wrappers
4. Role-gated admin/user areas
5. Unauthenticated login/register routes
6. NotFound catch-all

Route wrappers and roles:
- RefreshWrapper:
  runs on load and attempts auth refresh

- ApiInterceptors:
  adds auth header and handles token refresh-on-401

- AuthWrapper:
  blocks private routes for unauthenticated users

- RoleWrapper:
  splits ADMIN vs TRAVELER access

- UnauthWrapper:
  redirects authenticated users away from login/register

Route summary:

8. AUTH + SESSION MODEL
================================================================

Primary file:
- src/stores/authStore.ts

What it does:
- register
- login
- Google login
- refresh
- logout
- store user + token in Zustand
- mirror user/token/session markers into cookies

Important security note:
User and token are stored in client-readable cookies.
This is workable for a prototype, but is not the preferred hardened production model.

Other auth files:
- src/components/wrappers/RefreshWrapper.tsx
- src/components/wrappers/ApiInterceptors.tsx
- src/components/wrappers/AuthWrapper.tsx
- src/components/wrappers/RoleWrapper.tsx
- src/components/wrappers/UnauthWrapper.tsx

Role values seen in code:
- ADMIN
- TRAVELER
- GUIDE

Observed behavior:
- admin and traveler routes are actively wired
- guide role exists in types but does not appear to have a full dedicated route tree in this frontend

22. PRACTICAL RULES FOR ANOTHER AI
================================================================

Before answering a question:
1. Determine whether the question is about:
   - structure
   - runtime behavior
   - data source
   - UI
   - bug fixing
   - external service failure
2. If it touches Google APIs, do not blame only React without checking:
   - key
   - enabled APIs
   - quota/billing
   - coverage
3. If it touches auth or route access, inspect wrappers and authStore first.
4. If it touches mobile layout, inspect both the page and UserLayout.
5. If it touches notifications or top-right interactions, inspect TopBar first.

Before editing:
1. Identify whether the feature is mock-backed or API-backed.
2. Avoid breaking visual quality.
3. Prefer targeted edits to broad rewrites unless asked.
4. Run build after meaningful changes.

When describing the project:
Prefer:
"Frontend-only travel app with mixed live/demo features."
Avoid:
"Fully production-ready travel platform."
